# 本地视频库

> 一个纯前端、零后端、零依赖的本地视频管理工具。视频文件直接保存在浏览器 IndexedDB 中，无需账号、无需服务器，适合个人本地整理和管理视频。

## 1. 功能亮点

- ✨ **本地视频存储**：视频以 `Blob` 形式直接保存到浏览器 IndexedDB，不需要上传服务器。
- 📁 **分类管理**：支持添加、切换、重命名和删除分类。
- 🔄 **自动归类**：删除分类时，该分类下的视频会自动移动到「未分类」。
- 🎬 **即点即播**：点击视频卡片即可调用浏览器原生 HTML5 Video 播放器。
- 📤 **多选上传**：支持一次选择多个视频文件，也支持拖拽多个视频进行上传。
- ⬇️ **视频下载**：支持单个视频下载。
- ☑️ **批量选择**：可以在视频卡片上勾选多个视频。
- 📦 **批量下载**：一次选择多个视频后，可以连续触发下载。
- 🗑️ **批量删除**：支持一次删除多个选中的视频。
- 🔘 **当前分类全选**：可以快速选择当前分类下的全部视频。
- 🖼️ **自动生成缩略图**：上传视频时尝试从视频内容生成预览缩略图。
- 💾 **备份与恢复**：可以将整个视频库导出为 JSON，并在其他浏览器或设备中恢复。
- 📊 **存储监控**：使用浏览器 `StorageManager.estimate()` 获取可用时显示当前存储估算。
- 📱 **移动端适配**：手机端提供汉堡菜单、侧边栏、遮罩和响应式视频网格。
- 🌙 **响应式暗色界面**：适配桌面、平板和手机屏幕。
- 🔙 **旧数据兼容**：可以继续读取旧版本中以 Base64 形式保存的视频数据。
- 🚫 **零后端**：项目本身不需要数据库服务器、API 或用户账号。

## 2. 数据存储方式

项目采用浏览器本地存储：

```text
浏览器
│
├── LocalStorage
│   └── 分类配置
│       └── videoLib_cats_v1
│
└── IndexedDB
    └── VideoLibraryDB
        └── library
            └── videoLib_v1
                └── videos[]
                    ├── id
                    ├── Blob 视频文件
                    ├── name
                    ├── category
                    ├── size
                    ├── type
                    ├── createdAt
                    └── thumbnail

视频文件

新上传的视频不会先转换成 Base64，而是直接以 Blob 保存到 IndexedDB。

这样可以避免将视频长期保存为 Base64 所产生的额外体积膨胀。

分类数据

分类配置使用 LocalStorage 保存。

包括：

全部

未分类

教程

电影

音乐

其他

用户自定义分类


旧版本兼容

如果 IndexedDB 中存在旧版本数据，程序仍然可以识别：

Blob

ArrayBuffer

Base64 Data URL


因此升级版本后不需要强制重新导入旧视频。

3. 支持格式一览

格式	读取	写入	备注

.mp4	✅	✅	推荐格式，浏览器兼容性通常最好
.webm	✅	✅	现代浏览器支持较好
.mov	⚠️	✅	是否播放取决于浏览器及内部编码
.avi	⚠️	✅	浏览器对 AVI 支持有限
.mkv	⚠️	✅	播放能力取决于浏览器版本和编码
.ogv	⚠️	✅	浏览器支持情况不同
其他视频格式	⚠️	✅	由浏览器实际支持的 MIME 类型和视频编码决定
.json	✅	❌	仅用于视频库备份与恢复


> 上传成功不代表一定可以播放。
视频最终能否播放由浏览器的 HTML5 Video API、容器格式以及内部编码共同决定。



例如 MP4 文件本身也可能因为使用了当前浏览器不支持的视频编码而无法播放。

4. 上传与批量操作

多选上传

点击「上传视频」后，可以一次选择多个视频。

例如：

视频01.mp4
视频02.mp4
视频03.mp4
视频04.mp4

程序会依次：

1. 检查文件类型。


2. 检查单个文件大小。


3. 检查预计存储空间。


4. 尝试生成缩略图。


5. 将原始文件直接保存为 Blob。


6. 将所有视频写入 IndexedDB。



不会对视频进行转码或压缩。

拖拽上传

上传区域同时支持拖拽。

可以：

拖入一个视频

一次拖入多个视频


批量选择

视频卡片左上角提供选择框。

选择视频后，页面底部会出现批量操作栏：

已选 X 个    全选    ⬇ 下载    删除    取消

支持：

全选当前分类

取消全选

批量下载

批量删除

取消选择


> 连续下载多个文件时，部分浏览器可能会弹出“允许多个下载”的提示，需要允许浏览器执行多个下载。

5. 存储容量与文件限制

单个文件限制

当前程序设置：

最大单文件大小：2GB

这个限制是项目主动设置的安全阈值，并不是浏览器 IndexedDB 的真实容量上限。

整个视频库

项目没有人为设置类似：

5MB
10MB
100MB

这样的固定总容量。

实际可用空间由浏览器和设备决定，主要受到：

浏览器存储策略

操作系统

设备剩余空间

当前站点存储配额

浏览器隐私模式

浏览器版本


等因素影响。

程序会尝试通过：

navigator.storage.estimate()

获取浏览器提供的存储估算。

页面中的存储条因此属于估算值，不是绝对硬性容量上限。

注意

手机浏览器通常比桌面浏览器更容易遇到存储空间、内存或浏览器后台回收等问题。

如果需要保存大量视频，建议：

保持设备有足够剩余空间。

避免一次性导入大量超大视频。

定期导出备份。

不要随意清除网站数据。

6. 备份与恢复

项目提供完整的视频库备份功能。

备份内容包括：

视频文件

视频名称

分类

文件大小

文件类型

创建时间

视频缩略图

分类列表


备份格式

导出的文件为：

video-backup-YYYY-MM-DD.json

为了让备份文件能够独立迁移，导出时会暂时将 Blob 转换为 Base64 Data URL。

因此：

> 备份 JSON 的体积会明显大于原始视频文件。



例如一个较大的视频在转换为 Base64 并封装进 JSON 后，备份文件可能比原文件大约三分之一甚至更多。

恢复流程

恢复时：

JSON
 ↓
Base64
 ↓
Blob
 ↓
IndexedDB
 ↓
视频库

恢复后的新数据重新以 Blob 保存，而不会继续以 Base64 作为主要存储形式。

注意

大型视频库进行备份时会产生较大的内存压力。

手机端尤其建议：

不要一次备份过大的视频库。

必要时分批管理视频。

将备份文件保存到可靠位置。

7. 隐私与安全

所有视频数据均在当前浏览器本地处理。

项目本身不会主动将视频上传到第三方服务器。

没有账号体系。

不需要注册。

不需要后端数据库。

项目没有内置广告。

项目本身没有第三方行为追踪代码。

视频文件保存在当前浏览器的当前站点存储中。

不同浏览器、不同域名之间默认不会共享视频数据。


数据丢失风险

由于数据保存在浏览器本地，因此以下操作可能导致视频库丢失：

清除网站数据

清除浏览器存储

删除浏览器数据

某些隐私模式环境

浏览器或操作系统异常

设备故障

浏览器主动回收站点存储


因此重要视频建议定期使用：

导出备份 → 保存 JSON

进行备份。

12. 使用提示（踩坑经验）

1. MP4 文件无法播放

问题：

上传成功，但是播放器提示当前浏览器无法解码 MP4。

原因：

MP4 只是容器格式，内部的视频编码和音频编码仍然可能不被浏览器支持。

解决：

优先使用浏览器兼容性较好的 MP4，例如常见的：

H.264 + AAC

如果同一个文件在其他浏览器可以播放，而某个浏览器无法播放，通常属于浏览器自身的解码能力或兼容性问题。


---

2. 浏览器提示存储空间不足

问题：

上传大型视频时出现存储空间不足。

解决：

检查设备剩余空间，并删除不需要的视频或浏览器站点数据。

同时注意：

浏览器显示的 quota ≠ 设备硬盘剩余空间

浏览器可能根据自身存储策略限制网站可使用的空间。


---

3. 批量下载没有全部开始

问题：

选择多个视频后点击下载，但是浏览器没有全部下载。

原因：

现代浏览器可能限制网页连续触发多个下载。

解决：

如果浏览器弹出：

是否允许此网站下载多个文件？

选择允许。


---

4. 清除浏览器数据后视频消失

问题：

清除浏览器缓存 / 网站数据后，视频库为空。

原因：

视频不是存放在服务器，而是存放在浏览器的 IndexedDB 中。

解决：

清除网站数据前先：

导出备份 → 保存 JSON

之后可以使用「恢复备份」重新导入。


---

5. 更新网页后感觉旧界面还在

问题：

修改代码并重新部署后，浏览器仍然显示旧版本。

解决：

尝试强制刷新：

Ctrl + Shift + R

移动端可以关闭页面后重新打开，必要时清理网站缓存。


---

6. 不同设备之间看不到视频

问题：

电脑上传的视频，在手机打开网页后没有显示。

原因：

IndexedDB 是浏览器本地存储，不是云端数据库。

不同：

设备

浏览器

域名


之间默认不会共享数据。

解决：

在原设备：

导出备份

将 JSON 文件传到新设备后：

恢复备份

即可迁移视频库。

13. 数据生命周期

单个视频的大致生命周期：

选择视频
   ↓
File
   ↓
检查文件类型
   ↓
检查 2GB 单文件限制
   ↓
检查浏览器存储空间
   ↓
生成缩略图
   ↓
File → Blob
   ↓
IndexedDB
   ↓
Object URL
   ↓
HTML5 Video 播放
   ↓
删除视频
   ↓
IndexedDB 删除
   ↓
释放 Object URL

这样可以避免视频播放过程中长期依赖 Base64 字符串。
