本地视频库
一个纯前端、零后端、零依赖的本地视频管理工具。视频文件直接保存在浏览器 IndexedDB 中，无需账号、无需服务器，适合个人本地整理和管理视频。
HTML5 CSS3 JavaScript IndexedDB No Dependencies

1. 功能亮点
    • ✨ 本地视频存储：视频以 Blob 形式直接保存到浏览器 IndexedDB，不需要上传服务器。
    • 📁 分类管理：支持添加、切换和删除自定义分类。
    • 🔄 自动归类：删除自定义分类时，该分类下的视频会自动移动到「未分类」，视频本身不会被删除。
    • 🎬 即点即播：点击视频卡片即可调用浏览器原生 HTML5 Video 播放器。
    • 📤 多选上传：支持一次选择多个视频文件，也支持拖拽多个视频进行上传。
    • 🏷️ 视频标签：上传视频时可以添加多个标签，也可以之后编辑视频标签。
    • 🔎 标签筛选：可以按照当前分类下的标签筛选视频。
    • ▦ 网格视图：以视频卡片网格方式浏览视频。
    • ◷ 时间轴视图：按照视频创建时间倒序查看视频。
    • 🏷 标签视图：按照标签分组查看视频，没有标签的视频会单独归入「未添加标签」。
    • ✏️ 视频编辑：可以单独修改视频的分类和标签。
    • ☑️ 批量选择：可以在视频卡片上勾选多个视频。
    • 🔘 当前范围全选：可以快速选择当前分类和当前标签筛选结果中的全部视频。
    • ✏️ 批量编辑：可以同时修改多个视频的分类，也可以批量添加、替换、移除或清空标签。
    • ⬇️ 视频下载：支持单个视频下载。
    • 📦 批量下载：一次选择多个视频后，可以连续触发下载。
    • 🗑️ 批量删除：支持一次删除多个选中的视频。
    • 🖼️ 自动生成缩略图：上传视频时尝试从视频内容生成预览缩略图。
    • ♻️ 重复视频过滤：上传时可以自动跳过已经存在的视频，默认按照「文件名 + 文件大小」判断重复。
    • 💾 备份与恢复：可以将整个视频库导出为 JSON，并在其他浏览器或设备中恢复。
    • 📊 存储监控：使用 StorageManager.estimate() 获取可用时显示当前存储估算。
    • 📱 移动端适配：手机端提供汉堡菜单、侧边栏、遮罩、响应式网格和移动端批量操作栏。
    • 🌙 响应式界面：适配桌面、平板和手机屏幕。
    • 🔙 旧数据兼容：可以继续读取旧版本中以 Base64、ArrayBuffer 等形式保存的视频数据。
    • 🚫 零后端：项目本身不需要数据库服务器、API 或用户账号。

2. 数据存储方式
项目采用浏览器本地存储。
LocalStorage 用于保存分类配置，键名为 videoLib_cats_v1。
IndexedDB 使用 VideoLibraryDB 数据库和 library 对象仓库，视频库数据保存于 videoLib_v1。
每个视频主要包含：
id：视频唯一标识
blob：原始视频 Blob
name：视频名称
category：所属分类
tags：视频标签
size：文件大小
type：文件 MIME 类型
createdAt：创建时间
thumbnail：视频缩略图
新上传的视频不会先转换成 Base64，而是直接以 Blob 保存到 IndexedDB，这样可以避免视频长期以 Base64 字符串保存造成的额外体积膨胀。
分类数据使用 LocalStorage 保存。
默认分类包括：
📁 全部
📄 未分类
📚 教程
🎬 电影
🎵 音乐
📦 其他
用户可以创建自定义分类。
旧版本兼容方面，如果 IndexedDB 中存在旧版本数据，程序会尝试识别 Blob、ArrayBuffer 和 Base64 Data URL 等数据形式，因此升级后通常不需要重新导入旧视频。

3. 支持格式
.mp4：支持读取和写入，推荐使用，浏览器兼容性通常最好。
.webm：支持读取和写入，现代浏览器支持较好。
.mov：可以保存，但能否播放取决于浏览器以及内部编码。
.avi：可以保存，但浏览器播放支持有限。
.mkv：可以保存，但播放能力取决于浏览器版本和内部编码。
.ogv：可以保存，浏览器支持情况不同。
其他视频格式：可以尝试保存，实际播放能力由浏览器支持的 MIME 类型和视频编码决定。
.json：用于视频库备份与恢复，不作为视频文件格式。
上传成功不代表一定可以播放。视频最终能否播放由浏览器 HTML5 Video API、容器格式以及内部视频和音频编码共同决定。

4. 上传与重复视频过滤
点击「上传视频」后，可以一次选择多个视频，也可以将多个视频拖入上传区域。
上传时可以选择分类，并可以为本次上传的视频统一添加多个标签。
程序会依次：
    • 检查文件类型。
    • 检查单个文件大小。
    • 检查是否存在重复视频。
    • 检查预计存储空间。
    • 尝试生成缩略图。
    • 将原始文件直接保存为 Blob。
    • 将视频写入 IndexedDB。
不会对视频进行转码或压缩。
重复视频过滤默认开启。
重复判断采用：
文件名相同
    •  
文件大小相同
如果关闭「已上传的视频不显示」，则允许继续选择已经存在的视频。
需要注意，这不是文件内容哈希判断。如果两个不同的视频恰好具有相同的文件名和文件大小，也可能被认为是重复视频。

5. 视频浏览方式
当前提供三种浏览方式。
网格视图：
以常规视频卡片方式显示缩略图、名称、大小、日期、分类和标签。
时间轴视图：
按照视频创建时间从新到旧排列，可以直观看到视频的时间顺序。
标签视图：
按照视频标签分组显示。同一个视频拥有多个标签时，会出现在对应的多个标签分组中。
没有标签的视频会归入「未添加标签」。
三种视图可以随时切换，不会改变视频数据本身。

8. 存储容量与文件限制
单个文件限制：
最大单文件大小为 2GB。
这个限制是项目主动设置的安全阈值，并不是浏览器 IndexedDB 的真实容量上限。
整个视频库没有人为设置 5MB、10MB、100MB 等固定总容量。
实际可用空间由浏览器和设备决定，主要受到以下因素影响：
浏览器存储策略
操作系统
设备剩余空间
当前站点存储配额
浏览器隐私模式
浏览器版本
程序会尝试通过 navigator.storage.estimate() 获取浏览器提供的存储估算。
页面中的存储条属于估算值，不是绝对硬性容量上限。
手机浏览器通常比桌面浏览器更容易遇到存储空间、内存或后台回收问题。
如果需要保存大量视频，建议保持设备有足够剩余空间，避免一次性导入大量超大视频，并定期导出备份。

9. 备份与恢复
项目提供完整的视频库备份功能。
备份内容包括：
视频文件
视频名称
分类
标签
文件大小
文件类型
创建时间
分类列表
导出文件使用 JSON 格式。
为了让备份文件可以独立迁移，导出时会暂时将 Blob 转换为 Base64 Data URL。
因此备份 JSON 的体积会明显大于原始视频文件。
恢复流程为：
JSON
↓
Base64 Data URL
↓
Blob
↓
IndexedDB
↓
视频库
恢复后的新数据重新以 Blob 保存，而不会继续以 Base64 作为主要存储形式。
大型视频库进行备份时会产生较大的内存压力，手机端尤其不建议一次备份过大的视频库。
重要数据建议定期导出备份，并将 JSON 文件保存到可靠位置。

10. 隐私与安全
所有视频数据均在当前浏览器本地处理。
项目本身不会主动将视频上传到第三方服务器。
没有账号体系。
不需要注册。
不需要后端数据库。
项目没有内置广告。
项目本身没有第三方行为追踪代码。
视频文件保存在当前浏览器的当前站点存储中。
不同浏览器、不同域名和不同设备之间默认不会共享视频数据。
由于数据保存在浏览器本地，以下操作可能导致视频库丢失：
清除网站数据
清除浏览器存储
删除浏览器数据
使用某些隐私模式
浏览器或操作系统异常
设备故障
浏览器主动回收站点存储
因此重要视频建议定期使用「导出备份」保存 JSON。

16. 使用提示
MP4 文件无法播放：
MP4 只是容器格式，内部的视频编码和音频编码仍然可能不被当前浏览器支持。
优先使用浏览器兼容性较好的 MP4，例如 H.264 + AAC。
浏览器提示存储空间不足：
检查设备剩余空间，并删除不需要的视频或浏览器站点数据。
浏览器显示的 quota 不等于设备硬盘剩余空间。浏览器可能根据自身存储策略限制网站可使用的空间。
批量下载没有全部开始：
现代浏览器可能限制网页连续触发多个下载。
如果浏览器弹出是否允许此网站下载多个文件之类的提示，请允许多个下载。
清除浏览器数据后视频消失：
视频不是存放在服务器，而是存放在浏览器 IndexedDB 中。
清除网站数据前应先导出备份。
不同设备之间看不到视频：
IndexedDB 是浏览器本地存储，不是云端数据库。
不同设备、浏览器和域名之间默认不会共享视频数据。
可以在原设备导出 JSON 备份，再将 JSON 文件传到新设备后使用「恢复备份」。
